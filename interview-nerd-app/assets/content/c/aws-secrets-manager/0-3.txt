The response contains:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>SecretString</strong> or <strong>SecretBinary.</strong> The decrypted value. One or the other, never both.</li>\n<li><strong>VersionId.</strong> The unique identifier of the exact version you received. Useful for logging, and for telling whether a cached copy is stale.</li>\n<li><strong>VersionStages.</strong> An array of the staging labels attached to that version, for example <code>[\"AWSCURRENT\"]</code>. This tells you which role this version is currently playing.</li>\n<li><strong>ARN</strong>, <strong>Name</strong>, and <strong>CreatedDate</strong>. Identifying and timing metadata for the version.</li>\n</ul>\n<p style=\"line-height: 1.75\">Two things to note. This is the single most common \"why am I getting AccessDenied when my policy clearly allows GetSecretValue?\" cause. The tell is in the error message and in CloudTrail: the denied action will be <code>kms:Decrypt</code>, not <code>secretsmanager:GetSecretValue</code>. Read the error text carefully before changing anything.</p>\n<p style=\"line-height: 1.75\">Two related gotchas. A secret can also carry a <strong>resource-based policy</strong> — a policy attached to the secret itself rather than to the caller — and an explicit Deny there overrides any Allow in the caller's policy. This breaks in three independent ways:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>Cost.</strong> You are billed per API call — roughly 0.05 USD per 10,000 calls. A modest service handling 100 requests per second makes about 260 million calls a month, which is well over 1,000 USD in API charges for a value that changes once a quarter. Add KMS decrypt charges on top if you use a customer managed key.</li>\n<li><strong>Latency.</strong> Each call is a network round trip to a regional AWS endpoint, typically tens of milliseconds, plus TLS setup on a cold connection. You have added that to the front of every single user request, for no benefit.</li>\n<li><strong>Throttling.</strong> Secrets Manager enforces a per-account, per-region request rate limit on GetSecretValue. Exceed it and you get <code>ThrottlingException</code> responses — and because every request needs the secret, throttling does not degrade your service gracefully, it takes it down entirely. Worse, a traffic spike triggers it exactly when you can least afford an outage.</li>\n</ul>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Caching: The Central Practice</h4>\n<p style=\"line-height: 1.75\">The fix is to keep the fetched value in memory and reuse it. The simplest correct version is a <strong>module-level variable</strong> populated on first use — in Node.js, a module-scoped promise; in Python, a module-level global. They give you an in-memory cache with a configurable refresh interval and a maximum cache size, and a method to force a refresh. Java also has a JDBC driver wrapper that resolves credentials from a secret automatically.</p>\n<p style=\"line-height: 1.75\">For serverless workloads there is the <strong>AWS Parameters and Secrets Lambda Extension</strong>.
