Without cleanup, a repository accumulates thousands of images and you pay per GB-month forever. A <strong>lifecycle policy</strong> is a JSON set of rules ECR applies automatically to expire images — for example \"delete untagged images older than 7 days\" and \"keep only the 30 most recent images tagged with the prefix <code>v</code>\". Rules are evaluated by priority, lowest number first, and an image matched by one rule is not considered by later rules. Always keep enough history to roll back several versions, and be careful: a rule that deletes an image a running service still needs will break the next task launch or scale-out event.</p>\n<p style=\"line-height: 1.75\"><strong>Tag immutability</strong> is a per-repository setting. When enabled, pushing a tag that already exists is rejected. That means <code>v1.2.3</code> can never silently point at different content, which makes audits and rollbacks trustworthy. The consequence is that you can no longer push <code>latest</code> repeatedly — which is usually a feature, not a problem.
