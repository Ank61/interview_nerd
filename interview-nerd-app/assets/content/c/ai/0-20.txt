Do you ask the model to do all of it in <strong>one call</strong>, or break it into <strong>several calls</strong> where each one's output feeds the next? That is the whole question, and it comes up constantly because the instinct — one clever prompt that does everything — is usually wrong past a certain complexity.\n</p>\n<div style=\"padding: 2px; border-radius: 8px; font-size: 14px\">\n<div class=\"code\"><div class=\"code-head\"><span>code</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\">THE TASK: take a customer support email and produce a reply.\n\nSINGLE PROMPT\n  &quot;Read this email. Splitting gives each step the model's full attention.\n</p>\n<p style=\"line-height: 1.75; margin-top: 1.0rem\">\nBut the quality argument is only half of it. The bigger operational wins are:\n</p>\n<ol style=\"margin-top: 1.5rem; margin-left: 1.5rem; list-style-type: number\">\n<li style=\"margin-top: 0.5rem\">\n<span style=\"font-weight: 600; font-size: 1.1rem\">You can check between steps :</span>\nWith one prompt you get one blob at the end and either accept it or throw it away. With a chain you validate after each step — did the extraction produce a real order ID, did the classification return a valid label — and stop early when something is wrong instead of building four more steps on a bad foundation.\n</li>\n<li style=\"margin-top: 0.5rem\">\n<span style=\"font-weight: 600; font-size: 1.1rem\">You know which step failed :</span>\nThis is enormous for debugging. \"The reply was wrong\" is not actionable. \"Step 2 extracted the wrong order ID\" is a bug you can fix today.\n</li>\n<li style=\"margin-top: 0.5rem\">\n<span style=\"font-weight: 600; font-size: 1.1rem\">You can use a different model per step :</span>\nClassification and extraction go to a cheap fast model; only the genuinely hard reasoning step needs the expensive one. A five-step chain can easily cost <em>less</em> than one big call to a top-tier model.\n</li>\n<li style=\"margin-top: 0.5rem\">\n<span style=\"font-weight: 600; font-size: 1.1rem\">You can use different parameters per step :</span>\nTemperature 0 for extraction, 0.7 for drafting the reply. Impossible in a single call.\n</li>\n<li style=\"margin-top: 0.5rem\">\n<span style=\"font-weight: 600; font-size: 1.1rem\">Steps become reusable and testable :</span>\n\"Classify support request\" is now a component with its own golden set, used by three features.\n</li>\n</ol>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600; letter-spacing: -0.025em\">\nWhat Chaining Costs You\n</h4>\n<div style=\"padding: 2px; border-radius: 8px; font-size: 14px\">\n<div class=\"code\"><div class=\"code-head\"><span>code</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\">LATENCY - the big one.\n  Steps run in sequence, so latency ADDS UP.\n      1 call  x 2.0s              = 2.0s\n      5 calls x 1.2s (each simpler) = 6.0s\n  Three times slower, even though each step is faster.\n  MITIGATION: run independent steps IN PARALLEL. Split when you have a specific reason.</strong> Good reasons to split:\n</p>\n<ul style=\"margin-top: 1.0rem; margin-left: 1.5rem; list-style-type: disc\">\n<li style=\"margin-top: 0.5rem\">The single prompt is measurably failing on part of the task, and you can see which part.</li>\n<li style=\"margin-top: 0.5rem\">You need to <strong>validate</strong> an intermediate result before continuing — especially if a later step has a side effect.</li>\n<li style=\"margin-top: 0.5rem\">Different parts genuinely need different models, temperatures, or tools.</li>\n<li style=\"margin-top: 0.5rem\">One part is a hard branch — the path changes depending on an earlier answer.</li>\n<li style=\"margin-top: 0.5rem\">A sub-task is reusable elsewhere.</li>\n</ul>\n<p style=\"line-height: 1.75; margin-top: 1.0rem\">\nBad reasons to split: it feels more \"architectural\"; the diagram looks better; someone said chaining is best practice. Agents are flexible but non-deterministic, harder to evaluate, and can loop or wander.\n</p>\n<p style=\"line-height: 1.75; margin-top: 1.0rem\">\n<strong>Prefer a chain whenever the steps are known in advance.</strong> Most tasks people build agents for are actually fixed workflows with a couple of branches — and a chain will be faster, cheaper, more reliable and far easier to debug.
