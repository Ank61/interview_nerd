This topic is unglamorous, rarely prepared for, and enormously valuable in an interview — because everyone can describe embeddings, and very few can describe what happens when you feed a real enterprise document into a parser.\n</p>\n<p style=\"line-height: 1.75; margin-top: 1.5rem\">\nThe principle that governs the whole topic: <strong>garbage in, garbage out, silently.</strong> A parse failure does not throw. It produces text that is technically present and semantically useless, which then gets chunked, embedded, indexed and retrieved — and your assistant confidently answers from nonsense. Everything downstream is bounded by the quality of this stage.\n</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600; letter-spacing: -0.025em\">\nPart 1: Ingestion — Getting The Documents At All\n</h4>\n<p style=\"line-height: 1.75; margin-top: 1.0rem\">\nBefore you can parse anything you have to fetch it, and connecting to real enterprise systems is its own engineering problem.\n</p>\n<div style=\"padding: 2px; border-radius: 8px; font-size: 14px\">\n<div class=\"code\"><div class=\"code-head\"><span>code</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\">WHERE DOCUMENTS ACTUALLY LIVE\n  SharePoint / OneDrive     the classic enterprise nightmare\n  Confluence / Notion       wiki content, deeply nested\n  Google Drive              mixed formats, shared folders\n  S3 / blob storage         dumping ground, no metadata\n  Databases                 structured rows, not documents\n  Ticketing (Jira, Zendesk) threaded conversations\n  Email                     threads, quotes, attachments\n  Slack / Teams             chat, very different shape\n  Code repositories         needs completely different handling\n\nWHAT EACH CONNECTOR MUST HANDLE\n  Authentication      OAuth, service accounts, delegated access.\n                      Token refresh. Near-real-time and cheap. But webhooks get missed — a deploy, a network blip, an expired subscription — so you can never rely on them alone.\n</li>\n<li style=\"margin-top: 0.5rem\">\n<span style=\"font-weight: 600; font-size: 1.1rem\">Polling with a modified-since cursor :</span>\nAsk the source for everything changed since your last sync. Simple and reliable, but it depends on the source having an accurate modified timestamp, which is not always true — some systems bump it on trivial metadata changes, others do not update it at all when content changes through certain paths.\n</li>\n<li style=\"margin-top: 0.5rem\">\n<span style=\"font-weight: 600; font-size: 1.1rem\">Full reconciliation sweep (the safety net) :</span>\nPeriodically list everything in the source, compare against what you have indexed by ID and content hash, and fix the differences. This catches missed webhooks, timestamp lies, and — critically — <strong>deletions</strong>, which neither of the other approaches reliably reports. Run it nightly or weekly depending on corpus size.\n</li>\n</ol>\n<p style=\"line-height: 1.75; margin-top: 1.0rem\">\nThe mature answer is <strong>all three</strong>: webhooks for freshness, polling as the workhorse, reconciliation as the correctness guarantee. Extract <em>structured</em> text. Use a queue with retries and a dead-letter queue for permanent failures.</li>\n<li style=\"margin-top: 0.5rem\"><strong>Idempotent.</strong> Re-processing the same document must produce the same result and must not create duplicates. Key on a stable document ID plus a content hash.</li>\n<li style=\"margin-top: 0.5rem\"><strong>Resumable.</strong> A job over 100,000 documents will be interrupted. Checkpoint progress so a restart does not begin from zero.</li>\n<li style=\"margin-top: 0.5rem\"><strong>Deduplicated.</strong> Near-duplicate documents are extremely common in enterprises — the same policy in three places, a document and its own attachment copy. Hash content and skip exact duplicates; consider near-duplicate detection for the rest, because duplicates crowd out diversity in retrieval results.</li>\n<li style=\"margin-top: 0.5rem\"><strong>Versioned.</strong> Record a parser version on every document, so when you improve the parser you know which documents were processed with the old one and can selectively reprocess.</li>\n<li style=\"margin-top: 0.5rem\"><strong>Store the extracted text</strong> in a real database, not only as vectors.
