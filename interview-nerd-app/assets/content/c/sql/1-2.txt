{"title":"Indexes & Performance","tags":["Performance","Indexes","Optimization","Execution Plans"],"html":"<div>\n<p style=\"line-height: 1.75; margin-top: 1.5rem\">\nIndexes are database structures that improve the speed of data retrieval operations. They work like a book's index, allowing the database to find data without scanning every row. Understanding indexes and query execution is crucial for building high-performance database applications.\n</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600; letter-spacing: -0.025em\">\nTypes of Indexes\n</h4>\n<p style=\"line-height: 1.75; margin-top: 1rem\">\nDifferent index types serve different purposes. Choosing the right index type can dramatically improve query performance, while the wrong choice can actually hurt performance or waste storage space.\n</p>\n<div style=\"padding: 12px; border-radius: 8px; font-size: 14px; border: 1px solid #e9ecef\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- 1. CLUSTERED INDEX</i>\n<i class=c>-- Determines physical order of data in table</i>\n<i class=c>-- Only ONE per table (usually primary key)</i>\n<i class=c>-- Table data IS the index (leaf nodes contain actual data)</i>\n\n<i class=k>CREATE TABLE</i> employees (\n    employee_id <i class=t>INT</i> <i class=k>PRIMARY KEY</i>,  <i class=c>-- Automatically creates clustered index</i>\n    first_name <i class=t>VARCHAR</i>(<i class=n>50</i>),\n    last_name <i class=t>VARCHAR</i>(<i class=n>50</i>),\n    email <i class=t>VARCHAR</i>(<i class=n>100</i>),\n    department_id <i class=t>INT</i>,\n    salary <i class=t>DECIMAL</i>(<i class=n>10</i>,<i class=n>2</i>),\n    hire_date <i class=t>DATE</i>\n);\n\n<i class=c>-- Explicit clustered index creation (SQL Server)</i>\n<i class=k>CREATE</i> CLUSTERED INDEX idx_employee_id <i class=k>ON</i> employees(employee_id);\n\n<i class=c>-- Range queries are fast with clustered indexes</i>\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> employees \n<i class=k>WHERE</i> employee_id <i class=k>BETWEEN</i> <i class=n>1000</i> <i class=k>AND</i> <i class=n>2000</i>;  <i class=c>-- Very efficient</i>\n\n<i class=c>-- 2. SPATIAL INDEX</i>\n<i class=c>-- For geographic/spatial data (GIS applications)</i>\n\n<i class=k>CREATE</i> SPATIAL INDEX idx_location <i class=k>ON</i> stores(location);\n\n<i class=c>-- Find stores within radius</i>\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> stores \n<i class=k>WHERE</i> ST_Distance_Sphere(location, POINT(<i class=n>-74.0060</i>, <i class=n>40.7128</i>)) <i class=o>&lt;=</i> <i class=n>5000</i>;  <i class=c>-- 5km radius</i></code></pre></div>\n</div>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600; letter-spacing: -0.025em\">\nHow Indexes Improve Queries\n</h4>\n<p style=\"line-height: 1.75; margin-top: 1rem\">\nIndexes accelerate queries by reducing the amount of data the database must scan. Without an index, the database performs a full table scan, examining every row. With an index, it can quickly locate relevant data.\n</p>\n<div style=\"padding: 12px; border-radius: 8px; font-size: 14px; border: 1px solid #e9ecef\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- WITHOUT INDEX: Full Table Scan</i>\n<i class=c>-- Examines ALL rows in orders table (millions of rows)</i>\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> orders <i class=k>WHERE</i> customer_id <i class=o>=</i> <i class=n>12345</i>;\n<i class=c>-- Performance: O(n) - linear scan through entire table</i>\n\n<i class=c>-- WITH INDEX: Index Seek</i>\n<i class=k>CREATE</i> INDEX idx_customer <i class=k>ON</i> orders(customer_id);\n\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> orders <i class=k>WHERE</i> customer_id <i class=o>=</i> <i class=n>12345</i>;\n<i class=c>-- Performance: O(log n) - logarithmic search through B-tree</i>\n<i class=c>-- 1,000,000 rows: ~20 operations instead of 1,000,000</i>\n\n<i class=c>-- How indexes help different operations:</i>\n\n<i class=c>-- 1.  <i class=c>-- Index on orders.customer_id speeds EXISTS check</i>\n\n<i class=c>-- Query speed comparison:</i>\n<i class=c>-- Table: 10,000,000 orders</i>\n\n<i class=c>-- No index: ~45 seconds</i>\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> orders <i class=k>WHERE</i> customer_id <i class=o>=</i> <i class=n>12345</i>;\n\n<i class=c>-- With index: ~0.001 seconds (45,000x faster!)</i>\n<i class=k>CREATE</i> INDEX idx_customer <i class=k>ON</i> orders(customer_id);\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> orders <i class=k>WHERE</i> customer_id <i class=o>=</i> <i class=n>12345</i>;\n\n<i class=c>-- Composite index advantages:</i>\n<i class=k>CREATE</i> INDEX idx_customer_date <i class=k>ON</i> orders(customer_id, order_date);\n\n<i class=c>-- Very fast: Uses entire index</i>\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> orders \n<i class=k>WHERE</i> customer_id <i class=o>=</i> <i class=n>12345</i> <i class=k>AND</i> order_date <i class=o>&gt;</i> <i class=s>&#x27;2024-01-01&#x27;</i>;\n\n<i class=c>-- Still fast: Uses left portion of index</i>\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> orders <i class=k>WHERE</i> customer_id <i class=o>=</i> <i class=n>12345</i>;\n\n<i class=c>-- Slower: Cannot use index efficiently</i>\n<i class=k>SELECT</i> <i class=o>*</i> <i class=k>FROM</i> orders <i class=k>WHERE</i> order_date <i class=o>&gt;</i> <i class=s>&#x27;2024-01-01&#x27;</i>;
