ACID Properties Overview\n</h4>\n<p style=\"line-height: 1.75; margin-top: 1rem\">\nACID is an acronym that stands for Atomicity, Consistency, Isolation, and Durability. These properties guarantee that database transactions are processed reliably and ensure data integrity.\n</p>\n<h5 style=\"margin-top: 1rem; font-size: 1.1rem; font-weight: 600\">\nA - Atomicity\n</h5>\n<p style=\"line-height: 1.75; margin-top: 0.5rem\">\nAtomicity ensures that a transaction is treated as a single, indivisible unit of work. Either all operations within the transaction complete successfully, or none of them do.\n</p>\n<div style=\"padding: 1rem; border-radius: 8px; margin-top: 0.5rem\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- Bank transfer example demonstrating atomicity</i>\n<i class=k>BEGIN</i> TRANSACTION;\n\n<i class=c>-- Step 1: Deduct amount from sender&#x27;s account</i>\n<i class=k>UPDATE</i> accounts \n<i class=k>SET</i> balance <i class=o>=</i> balance <i class=o>-</i> <i class=n>500.00</i>,\n    last_updated <i class=o>=</i> <i class=b>CURRENT_TIMESTAMP</i>\n<i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>;\n\n<i class=c>-- Step 2: Add amount to receiver&#x27;s account  </i>\n<i class=k>UPDATE</i> accounts \n<i class=k>SET</i> balance <i class=o>=</i> balance <i class=o>+</i> <i class=n>500.00</i>,\n    last_updated <i class=o>=</i> <i class=b>CURRENT_TIMESTAMP</i>\n<i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>102</i>;\n\n<i class=c>-- Step 3: Record the transaction</i>\n<i class=k>INSERT INTO</i> transactions (from_account, to_account, amount, trans_date, trans_type)\n<i class=k>VALUES</i> (<i class=n>101</i>, <i class=n>102</i>, <i class=n>500.00</i>, <i class=b>CURRENT_TIMESTAMP</i>, <i class=s>&#x27;TRANSFER&#x27;</i>);\n\n<i class=c>-- If any step fails, the entire transaction is rolled back</i>\n<i class=k>COMMIT</i>;\n<i class=c>-- or ROLLBACK; if an error occurs</i>\n\n<i class=c>-- Atomicity ensures:</i>\n<i class=c>-- Either ALL three operations succeed, or NONE of them do</i>\n<i class=c>-- No partial updates where money is deducted but not added</i></code></pre></div>\n</div>\n<h5 style=\"margin-top: 1rem; font-size: 1.1rem; font-weight: 600\">\nC - Consistency\n</h5>\n<p style=\"line-height: 1.75; margin-top: 0.5rem\">\nConsistency ensures that a transaction brings the database from one valid state to another, maintaining all database rules, constraints, and invariants.\n</p>\n<div style=\"padding: 1rem; The operations in one transaction are hidden from other transactions until the first transaction is committed.\n</p>\n<div style=\"padding: 1rem; border-radius: 8px; margin-top: 0.5rem\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- Session 1: Transaction A</i>\n<i class=k>BEGIN</i> TRANSACTION;\n<i class=k>UPDATE</i> accounts <i class=k>SET</i> balance <i class=o>=</i> balance <i class=o>-</i> <i class=n>200.00</i> <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>;\n<i class=c>-- Balance is now 4800.00 in this transaction, but other sessions still see 5000.00</i>\n\n<i class=c>-- Session 2: Transaction B (concurrent)</i>\n<i class=k>BEGIN</i> TRANSACTION;\n<i class=k>SELECT</i> balance <i class=k>FROM</i> accounts <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>; \n<i class=c>-- Still sees 5000.00 (not the uncommitted change from Transaction A)</i>\n\n<i class=c>-- Session 1: Commit the changes</i>\n<i class=k>COMMIT</i>;\n\n<i class=c>-- Session 2: Now sees the updated balance</i>\n<i class=k>SELECT</i> balance <i class=k>FROM</i> accounts <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>; <i class=c>-- Sees 4800.00</i>\n\n<i class=c>-- Isolation prevents:</i>\n<i class=c>-- * Dirty reads (reading uncommitted data)</i>\n<i class=c>-- * Non-repeatable reads (data changing during a transaction)</i>\n<i class=c>-- * Phantom reads (new rows appearing during a transaction)</i></code></pre></div>\n</div>\n<h5 style=\"margin-top: 1rem; font-size: 1.1rem; font-weight: 600\">\nD - Durability\n</h5>\n<p style=\"line-height: 1.75; margin-top: 0.5rem\">\nDurability guarantees that once a transaction is committed, its changes are permanent and will survive system failures (power loss, crashes, etc.).\n</p>\n<div style=\"padding: 1rem; border-radius: 8px; margin-top: 0.5rem\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- Durability in action</i>\n<i class=k>BEGIN</i> TRANSACTION;\n\n<i class=c>-- Critical financial operation</i>\n<i class=k>UPDATE</i> accounts <i class=k>SET</i> balance <i class=o>=</i> balance <i class=o>+</i> <i class=n>1000.00</i> <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>103</i>;\n<i class=k>INSERT INTO</i> transactions (to_account, amount, trans_type) \n<i class=k>VALUES</i> (<i class=n>103</i>, <i class=n>1000.00</i>, <i class=s>&#x27;DEPOSIT&#x27;</i>);\n\n<i class=c>-- Once committed, the changes are permanent</i>\n<i class=k>COMMIT</i>;\n\n<i class=c>-- Even if:</i>\n<i class=c>-- * Database server crashes immediately after COMMIT</i>\n<i class=c>-- * Power failure occurs</i>\n<i class=c>-- * Hardware fails</i>\n<i class=c>-- The committed transaction will be recovered and persisted</i>\n\n<i class=c>-- Database mechanisms ensuring durability:</i>\n<i class=c>-- * Write-Ahead Logging (WAL)</i>\n<i class=c>-- * Transaction logs</i>\n<i class=c>-- * Checkpointing</i>\n<i class=c>-- * Redo logs</i></code></pre></div>\n</div>\n<h4 style=\"margin-top: 1.5rem; Different levels provide different trade-offs between consistency and performance.\n</p>\n<h5 style=\"margin-top: 1rem; font-size: 1.1rem; font-weight: 600\">\nConcurrency Problems\n</h5>\n<div style=\"padding: 1rem; border-radius: 8px; margin-top: 0.5rem\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- 1. Dirty Read: Reading uncommitted data</i>\n<i class=c>-- Transaction A</i>\n<i class=k>BEGIN</i>;\n<i class=k>UPDATE</i> accounts <i class=k>SET</i> balance <i class=o>=</i> <i class=n>6000.00</i> <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>; <i class=c>-- Not committed yet</i>\n\n<i class=c>-- Transaction B (with READ UNCOMMITTED)</i>\n<i class=k>SET</i> TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;\n<i class=k>SELECT</i> balance <i class=k>FROM</i> accounts <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>; <i class=c>-- Sees 6000.00 (dirty read)</i>\n\n<i class=c>-- Transaction A rolls back</i>\n<i class=k>ROLLBACK</i>;\n\n<i class=c>-- Now Transaction B has seen data that never truly existed!</i>\n\n<i class=c>-- 2. Non-repeatable Read: Data changed during transaction</i>\n<i class=c>-- Transaction A</i>\n<i class=k>BEGIN</i>;\n<i class=k>SELECT</i> balance <i class=k>FROM</i> accounts <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>; <i class=c>-- Returns 5000.00</i>\n\n<i class=c>-- Transaction B</i>\n<i class=k>UPDATE</i> accounts <i class=k>SET</i> balance <i class=o>=</i> <i class=n>4500.00</i> <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>;\n<i class=k>COMMIT</i>;\n\n<i class=c>-- Transaction A (same transaction)</i>\n<i class=k>SELECT</i> balance <i class=k>FROM</i> accounts <i class=k>WHERE</i> account_id <i class=o>=</i> <i class=n>101</i>; <i class=c>-- Now returns 4500.00!</i>\n<i class=c>-- Same query, different results within same transaction</i>\n\n<i class=c>-- 3. Phantom Read: New rows appearing</i>\n<i class=c>-- Transaction A</i>\n<i class=k>BEGIN</i>;\n<i class=k>SELECT</i> <i class=b>COUNT</i>(<i class=o>*</i>) <i class=k>FROM</i> accounts <i class=k>WHERE</i> balance <i class=o>&gt;</i> <i class=n>1000.00</i>; <i class=c>-- Returns 3</i>\n\n<i class=c>-- Transaction B</i>\n<i class=k>INSERT INTO</i> accounts (account_id, account_holder, balance) \n<i class=k>VALUES</i> (<i class=n>104</i>, <i class=s>&#x27;New Customer&#x27;</i>, <i class=n>2000.00</i>);\n<i class=k>COMMIT</i>;\n\n<i class=c>-- Transaction A</i>\n<i class=k>SELECT</i> <i class=b>COUNT</i>(<i class=o>*</i>) <i class=k>FROM</i> accounts <i class=k>WHERE</i> balance <i class=o>&gt;</i> <i class=n>1000.00</i>; <i class=c>-- Now returns 4!</i>\n<i class=c>-- New &quot;phantom&quot; row appeared</i></code></pre></div>\n</div>\n<h5 style=\"margin-top: 1rem; font-size: 1.1rem; font-weight: 600\">\nStandard Isolation Levels\n</h5>\n<div style=\"padding: 1rem; border-radius: 8px; margin-top: 0.5rem\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- 1. style=\"margin-top: 1rem; font-size: 1.1rem; font-weight: 600\">\nInventory Management with Optimistic Locking\n</h5>\n<div style=\"padding: 1rem; border-radius: 8px; margin-top: 0.5rem\" data-box=\"1\">\n<div class=\"code\"><div class=\"code-head\"><span>sql</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c>-- Inventory table with
