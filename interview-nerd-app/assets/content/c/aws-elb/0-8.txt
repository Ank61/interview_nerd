You pick a region mainly for closeness to your users and for data-residency rules. This is the single most important concept on this page.</li>\n<li><strong>VPC (Virtual Private Cloud).</strong> Your own private, isolated network inside AWS, spanning one region. The console will not let you proceed with one.</p>\n<p style=\"line-height: 1.75\">The reason is that <strong>the load balancer itself must not be a single point of failure</strong>. AWS places a load balancer <strong>node</strong> — an actual piece of running infrastructure — in each Availability Zone you select, and publishes the addresses of all those nodes under the load balancer's single DNS name. When a client resolves that name, it may get any of them. If an entire data centre goes dark, the nodes in the surviving zones keep answering and the DNS entry for the failed one is withdrawn.</p>\n<p style=\"line-height: 1.75\">Think about the alternative. You carefully spread ten application servers across two zones for resilience, then put the load balancer in one zone. Lose that zone and <strong>all ten servers become unreachable</strong>, because the only door to them is gone. Every bit of redundancy behind the load balancer is wasted. Multi-zone is not paranoia; it is the minimum for the whole design to mean anything.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">The standard secure layout</h4>\n<p Your application servers have <strong>no public IP addresses and no route from the internet</strong>, so an attacker cannot connect to them at all — not to SSH, not to a stray admin port, not to a debug endpoint you forgot to close. The only traffic they accept is what their <strong>security group</strong> (the virtual firewall around each resource) permits from the load balancer's security group, on one port. The database accepts connections only from the application servers' security group. Each layer can only be reached from the layer in front of it.</p>\n<p style=\"line-height: 1.75\">And note the crucial point that trips people up: <strong>your application servers do not need public subnets to be reachable through the load balancer.</strong> The load balancer sits in a public subnet, receives the internet connection there, and then makes a fresh connection to the target over private addressing inside the VPC.
