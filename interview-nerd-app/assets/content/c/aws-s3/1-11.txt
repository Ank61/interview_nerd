Rather than examining one bucket at a time, Storage Lens aggregates metrics across every bucket in an account — or, with Organizations trusted access enabled, across every account in an AWS Organization — and presents them through interactive dashboards or as exportable metrics files. AWS explicitly positions Storage Lens as the recommended tool for <strong>understanding, analyzing, and optimizing storage usage and cost at scale</strong> across an entire S3 footprint.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">What Storage Lens tracks</h4>\n<p style=\"line-height: 1.75\">Storage Lens organizes dozens of metrics into a few practical categories:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>Storage usage.</strong> Total bytes stored, object counts, and how both are trending over time, broken down by bucket, storage class, and (in advanced tier) prefix or account.</li>\n<li><strong>Storage class distribution.</strong> How much data sits in STANDARD vs. STANDARD-IA vs. GLACIER vs. INTELLIGENT_TIERING, letting you spot data that never transitioned out of expensive tiers.</li>\n<li><strong>Incomplete multipart uploads.</strong> Bytes consumed by multipart uploads that were started but never completed or aborted — a common source of silent, unnecessary storage cost.</li>\n<li><strong>Versioning metrics.</strong> Noncurrent version count and bytes, which often balloon unnoticed in versioned buckets without a lifecycle rule to expire old versions.</li>\n<li><strong>Activity metrics (advanced tier).</strong> Request counts (GET, PUT, LIST, DELETE), bytes downloaded/uploaded, and error rates — useful for understanding access patterns, not just stored footprint.</li>\n<li><strong>Encryption and replication configuration status.</strong> Advanced-tier metrics can flag buckets lacking default encryption or replication, feeding directly into security posture reviews.</li>\n</ul>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Default dashboard vs. custom dashboards</h4>\n<p style=\"line-height: 1.75\">Every account automatically gets a <strong>default dashboard</strong> at no charge, scoped to that account, using the \"free\" metrics tier — storage usage, object counts, and basic activity summaries updated daily. Because it's provisioned automatically, it requires no setup for a baseline view. Beyond that, you can create <strong>custom dashboards</strong> scoped to specific accounts, regions, or bucket groups, and optionally enable the paid <strong>advanced metrics and recommendations tier</strong>, which unlocks activity metrics, advanced data protection metrics, prefix-level aggregation, CloudWatch publishing, and 15-month data retention (versus 14 days for free-tier metrics). Custom dashboards can also export raw metrics as CSV or Parquet to an S3 bucket for further analysis, mirroring how Inventory exports work.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Organization-wide visibility</h4>\n<p style=\"line-height: 1.75\">In a multi-account AWS Organization, an account designated to run Storage Lens can be granted trusted access to aggregate metrics from every member account into one dashboard — without needing to assume a role into each account manually. This is the feature that makes Storage Lens genuinely useful at enterprise scale: a central cloud/FinOps team can see, from one screen, that Account B's data lake has grown 3x quarter over quarter, or that fifteen accounts collectively have petabytes sitting in STANDARD that qualify for Intelligent-Tiering, without chasing down each account owner individually.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">How Storage Lens drives cost decisions in practice</h4>\n<p style=\"line-height: 1.75\">Storage Lens's dashboard includes a built-in <strong>cost-optimization / recommendations view</strong> that surfaces actionable signals: buckets with large amounts of data still on STANDARD past a typical access-decline point, buckets with high incomplete-multipart-upload bytes, buckets with rapidly growing noncurrent version storage, or buckets lacking lifecycle configuration altogether. Engineers act on these signals by writing lifecycle rules (e.g., transition to Intelligent-Tiering or Glacier, expire noncurrent versions, or abort incomplete multipart uploads after N days) targeted at the specific buckets Storage Lens flagged — rather than guessing which buckets across an entire organization need attention.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Interview scenario: shrinking a runaway storage bill</h4>\n<p style=\"line-height: 1.75\">Imagine your S3 bill has grown 25% quarter over quarter and nobody knows why. The efficient investigation path is: open the Storage Lens default (or custom) dashboard, sort by month-over-month byte growth per bucket, and check the incomplete-multipart-upload and noncurrent-version-bytes metrics for the fastest-growing buckets. Suppose it reveals one ingestion bucket has 40 TB of incomplete multipart uploads from a misbehaving client that retries uploads without aborting failed parts.
