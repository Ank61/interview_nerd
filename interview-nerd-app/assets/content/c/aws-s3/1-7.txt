As an organization scales, that single policy accumulates dozens of conditional statements — one block per team, per application, per environment — and becomes fragile and hard to audit. An Access Point solves this by giving each application its own dedicated entry point into the bucket: its own <strong>ARN</strong>, its own <strong>hostname</strong>, and its own <strong>access point policy</strong> that is evaluated in addition to (not instead of) the underlying bucket policy. Optionally, an access point can be restricted to a <strong>VPC-only network origin</strong>, meaning it only accepts requests arriving through a specific VPC — a powerful way to guarantee that only workloads inside a particular private network can use that access path, regardless of what IAM permissions a caller might otherwise have.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">The Mental Model</h4>\n<p style=\"line-height: 1.75\">Picture one shared bucket, <code>company-data-lake</code>, with three access points attached to it: <strong>Access Point A</strong> for the Analytics team (read-only, scoped to the <code>analytics/</code> prefix), <strong>Access Point B</strong> for the Finance application (read/write, scoped to <code>finance/</code>, VPC-restricted to the finance VPC), and <strong>Access Point C</strong> for an external partner integration (read-only, scoped to <code>partner-exports/</code>, restricted by a specific IAM role). Each team connects to its own access point ARN, sees only what its policy allows, and none of them need to see or reason about the others' rules. The underlying bucket policy can stay minimal — often just delegating trust to the access points themselves — while the fine-grained logic lives closer to the consumer it's meant for.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Access Point ARNs</h4>\n<p style=\"line-height: 1.75\">Because an access point has its own identity, it's referenced by its own <strong>ARN</strong> (for example, <code>arn:aws:s3:us-east-1:111122223333:accesspoint/finance-ap</code>) rather than by bucket name — and API calls, SDK requests, and IAM policies can target that ARN directly wherever an S3 bucket/object ARN would normally be used.
