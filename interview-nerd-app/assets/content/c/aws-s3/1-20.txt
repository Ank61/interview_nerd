This is one of the most common serverless patterns on AWS — thumbnail generation, virus scanning, log processing, and format conversion pipelines almost always start with an <strong>s3:ObjectCreated:*</strong> event. On failure, Lambda automatically retries the invocation (by default, up to two additional attempts with a delay between them). The fix is architectural, not just a code guard: <strong>separate the input and output locations</strong>. The standard solution is <strong>raw-bucket → Lambda → processed-bucket</strong>: the trigger listens on a \"raw\" bucket, and the function writes its output to a completely different \"processed\" bucket that has no trigger configured at all, making recursion structurally impossible.
