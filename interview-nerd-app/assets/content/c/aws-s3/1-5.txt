S3 event notification delivery is guaranteed to be <strong>at-least-once, not exactly-once</strong>. In rare cases — network retries, internal S3 delivery retries, or a downstream service acknowledging late — the same event can be delivered more than once. The correct answer is not \"prevent duplicates\" (you generally cannot), but rather: <strong>design every consumer to be idempotent</strong>. For example, a Lambda resizing an image should overwrite the same output key on each invocation rather than appending, and a database-updating consumer should use an upsert keyed by the S3 object key and version ID rather than an insert.
