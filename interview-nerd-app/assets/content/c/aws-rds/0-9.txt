{"title":"Parameter Groups, Option Groups, and Maintenance Windows","tags":["parameter-groups","option-groups","maintenance","rds-configuration"],"html":"<div>\n<p style=\"line-height: 1.75; margin-top: 1.5rem\">When you run a database on your own laptop or your own server, you configure it by editing a text file — <code>my.cnf</code> for MySQL, <code>postgresql.conf</code> for PostgreSQL — and you patch it by running the operating system's update command whenever you feel like it. With <strong>Amazon RDS</strong> you get neither: AWS manages the operating system and does not give you a login to the server. So AWS replaces those two abilities with structured equivalents: <strong>parameter groups</strong> and <strong>option groups</strong> for changing settings, and <strong>maintenance windows</strong> for controlling when AWS patches things.</p>\n<p style=\"line-height: 1.75\">This trade is the whole point of a managed service. You give up shell access and gain the guarantee that AWS handles patching, backups, and failover. Understanding these three mechanisms is what turns \"I can click Create Database\" into \"I can operate a database\".</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Parameter groups: your config file, as an AWS resource</h4>\n<p style=\"line-height: 1.75\">A <strong>DB parameter group</strong> is a named collection of database engine settings that you attach to one or more instances. Every setting you would have written into <code>postgresql.conf</code> lives here instead — memory allocation, timeouts, logging verbosity, connection limits, and so on.</p>\n<p style=\"line-height: 1.75\">Two structural facts follow from it being a separate resource:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>One group, many instances.</strong> You can attach the same parameter group to ten instances and change all ten consistently by editing one thing.</li>\n<li><strong>It is versioned to an engine family.</strong> A group is created for a specific family such as <code>postgres16</code> or <code>mysql8.0</code>, because the available settings differ between engine versions.</li>\n</ul>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">The default parameter group is read-only</h4>\n<p style=\"line-height: 1.75\">Every new instance is attached to a <strong>default parameter group</strong> (for example <code>default.postgres16</code>) unless you say otherwise. On MySQL, <code>slow_query_log = 1</code> with <code>long_query_time = 1</code>.
