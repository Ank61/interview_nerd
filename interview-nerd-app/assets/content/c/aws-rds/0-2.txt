A database keeps a chunk of recently used data in memory — MySQL calls this the InnoDB buffer pool, PostgreSQL calls it shared buffers — because reading from RAM is dramatically faster than reading from disk. When a query needs a row that is already in memory, the answer comes back in microseconds. When it is not, the database must go to disk, which is orders of magnitude slower.</p>\n<p style=\"line-height: 1.75\">Think of it like a desk and a filing cabinet. Memory is your desk: whatever is on it, you can grab instantly. Disk is the cabinet down the hall. A bigger desk means fewer trips. If the slice of your data that gets touched regularly — often called the <strong>working set</strong> — fits comfortably in memory, your database feels fast. If it does not, every query risks a trip to the cabinet.</p>\n<p style=\"line-height: 1.75\">That is precisely why memory-optimized classes exist.
