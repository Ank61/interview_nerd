{"title":"What Is Amazon RDS — A Managed Relational Database Service","tags":["aws","rds","managed service","fundamentals"],"html":"<div>\n<p style=\"line-height: 1.75; margin-top: 1.5rem\"><strong>Amazon RDS (Relational Database Service)</strong> is AWS running a normal SQL database for you — MySQL, PostgreSQL, and a few others — on a server you never log into. A <strong>relational database</strong> is the familiar kind you have probably already used: data is stored in <strong>tables</strong> made of <strong>rows</strong> (one record each) and <strong>columns</strong> (one field each), and you ask questions with <strong>SQL</strong>. RDS does not change any of that. The SQL you write on your laptop is the SQL you write against RDS. What changes is who does the boring, risky, never-ending work of keeping that database alive.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">What \"Managed\" Actually Means</h4>\n<p style=\"line-height: 1.75\">\"Managed\" is a marketing word until you list the chores it covers. For RDS it means AWS provisions the machine, installs the database software, applies security patches to the operating system and the database engine, takes automatic backups on a schedule, and — if you ask for it — keeps a second synchronized copy of your database in another building so that if the first machine dies, traffic moves to the copy automatically.</p>\n<p style=\"line-height: 1.75\">That last one has a name you will hear constantly: <strong>failover</strong>, which simply means \"automatically switching over to a standby copy when the main one fails.\" The standby is a second server holding the same data. RDS keeps it in sync and flips to it without you waking up at 3am.</p>\n<p style=\"line-height: 1.75\">You interact with your database through an <strong>endpoint</strong> — a DNS hostname AWS gives you, like <code>myapp-db.abc123xyz.us-east-1.rds.amazonaws.com</code>, that your application connects to instead of an IP address. This matters more than it sounds: when a failover happens, AWS repoints that same hostname at the standby machine, so your application's connection string never has to change.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">The Do-It-Yourself Version: What You Would Do on a Plain Server</h4>\n<p style=\"line-height: 1.75\">To appreciate RDS, walk through what you would do if you rented a bare virtual server from AWS — that is <strong>EC2 (Elastic Compute Cloud)</strong>, AWS's service for renting virtual machines you fully control — and installed PostgreSQL on it yourself. Here is the honest list:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>Provision the server.</strong> Pick a machine size, pick an operating system image, attach a disk, put it on a network, open the right firewall ports.</li>\n<li><strong>Install and configure the database.</strong> Add the package repository, install the engine, edit the config files for memory settings, connection limits, and logging, then tune them for your hardware.</li>\n<li><strong>Set up backups.</strong> Write a script that dumps or snapshots the data, put it on a schedule, ship the output somewhere durable, and rotate old copies so the disk does not fill up.</li>\n<li><strong>Test the restores.</strong> A backup you have never restored is a rumor, not a backup. This means periodically standing up a fresh server and proving the data comes back.</li>\n<li><strong>Apply security patches.</strong> Both the operating system and the database engine ship fixes regularly. You track them, schedule a maintenance window, patch, and pray nothing breaks.</li>\n<li><strong>Build your own failover.</strong> Stand up a second server, configure replication between them, install software to detect failure, and write the logic that promotes the standby and redirects traffic. This is genuinely hard to get right.</li>\n<li><strong>Monitor disk space.</strong> A database that fills its disk stops accepting writes and often refuses to start. You need alarms, and someone to act on them.</li>\n</ul>\n<p style=\"line-height: 1.75\">RDS takes over every single item on that list. You still choose the settings, but AWS performs the work. That is the whole value proposition, and it is a large one — this list is a part-time job for a person who would rather be shipping features.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">What You Give Up</h4>\n<p style=\"line-height: 1.75\">This trade is real and an interviewer will respect you for naming it honestly. In exchange for the operational relief, you lose direct control of the machine:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>No operating-system access.</strong> You cannot <strong>SSH</strong> into an RDS host. (SSH is the standard way of opening a remote command-line session on a server.) There is no shell, no <code>top</code>, no poking at log files on disk. You see the database through AWS's console, metrics, and downloadable log files instead.</li>\n<li><strong>No arbitrary software on the host.</strong> You cannot install a monitoring agent, a custom backup daemon, or a sidecar process next to the database.</li>\n<li><strong>Only supported extensions and features.</strong> PostgreSQL extensions, for example, must be on the list RDS supports. A niche extension that needs to load native code from the filesystem generally will not work.</li>\n<li><strong>No superuser.</strong> Your \"master user\" is powerful but deliberately not the engine's true superuser account, because a true superuser could break the managed layer AWS depends on.</li>\n<li><strong>Patching is on AWS's calendar, with your input.</strong> You choose a weekly <strong>maintenance window</strong> — a time slot when AWS is allowed to apply updates — but you do not get to defer some updates forever.</li>\n</ul>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Where RDS Sits: RDS vs Database-on-EC2 vs DynamoDB</h4>\n<p style=\"line-height: 1.75\">Beginners often confuse these three.
