The <strong>default is 3 seconds</strong>; the <strong>maximum is 900 seconds (15 minutes)</strong>. When the timeout is reached Lambda terminates the invocation, writes a <em>Task timed out after N seconds</em> line to CloudWatch Logs, and counts it as an error. Your code gets no clean shutdown hook for this, so any partially written state stays partially written — which is why idempotency matters.</p>\n<p style=\"line-height: 1.75\">Choosing a timeout is a design decision, not a formality. Two failure modes bracket the choice:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>Too short.</strong> The 3-second default silently kills functions that call a cold database or a slow third-party API. Beginners routinely deploy, see intermittent failures, and blame the network.</li>\n<li><strong>Too long.</strong> A function stuck waiting on an unresponsive dependency burns the full timeout on every invocation. You pay for all of it, you hold a concurrency slot for all of it, and a downstream outage turns into a throttling incident upstream.</li>\n</ul>\n<p style=\"line-height: 1.75\">The sound rule: set the timeout a little above the <strong>worst realistic end-to-end latency</strong> of your downstream dependencies — for example, p99 latency plus your retry budget plus a margin — and configure your AWS SDK client's own request timeout and retry count so the SDK gives up <em>before</em> Lambda does. That way you fail with a useful error message instead of an opaque timeout. Also remember that for synchronous invocations there may be a shorter limit in front of Lambda: <strong>API Gateway REST and HTTP APIs have their own integration timeout</strong>, so a 15-minute Lambda behind API Gateway will still return a 504 to the caller long before it finishes.</p>\n<p style=\"line-height: 1.75\">The runtime tells your handler how much time is left. Their point is <strong>separating configuration from code</strong>: the same deployment package can point at a dev table in one account and a prod table in another, and you can change a log level or a feature flag by updating configuration, with <em>no code redeployment</em>.</p>\n<p style=\"line-height: 1.75\">Key properties worth knowing precisely:</p>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>Encrypted at rest by default.</strong> Lambda encrypts environment variables using an AWS managed KMS key; you may supply your own customer managed key instead, and you may additionally enable client-side encryption of specific values (encryption helpers) so they are not readable in the console.</li>\n<li><strong>Size limit.</strong> The total size of all environment variables for a function is capped at <strong>4 KB</strong>. That is small — it rules out stuffing certificates or large config blobs in there.</li>\n<li><strong>Visible to anyone with configuration read access.</strong> <code>lambda:GetFunctionConfiguration</code> returns them in plaintext, and the console displays them. \"Encrypted at rest\" does not mean \"hidden from your teammates\".</li>\n<li><strong>Reserved names.</strong> The runtime sets its own variables — <code>AWS_REGION</code>, <code>AWS_LAMBDA_FUNCTION_NAME</code>, <code>AWS_LAMBDA_FUNCTION_MEMORY_SIZE</code>, <code>AWS_LAMBDA_LOG_GROUP_NAME</code>, and the credential variables <code>AWS_ACCESS_KEY_ID</code>, <code>AWS_SECRET_ACCESS_KEY</code>, <code>AWS_SESSION_TOKEN</code>. Some are reserved and cannot be overridden.</li>\n<li><strong>Read once, at Init.</strong> Because the values are baked into the execution environment when it starts, changing a variable only affects environments created afterwards. Updating configuration causes new environments to be used for subsequent invocations.</li>\n</ul>\n<p style=\"line-height: 1.75\">The security rule every interviewer wants to hear: <strong>secrets do not belong in plaintext environment variables.</strong> Database passwords, third-party API keys and tokens belong in <strong>AWS Secrets Manager</strong> (which supports automatic rotation) or in <strong>AWS Systems Manager Parameter Store</strong> as a <em>SecureString</em> (cheaper, no built-in rotation).
