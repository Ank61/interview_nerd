Image Tagging Strategies\n</h4>\n<p style=\"line-height: 1.75; margin-top: 1rem\">\nTagging strategy determines traceability, rollback capability, and release management. The naive use of <code>:latest</code> is widely considered an anti-pattern for production because it destroys the ability to know exactly which version is running.\n</p>\n<div style=\"margin-top: 1rem; border-left: 4px solid #eab308; padding: 1rem; border-radius: 4px; font-size: 0.9rem\" data-box=\"1\">\n<strong>⚠️ The :latest Anti-pattern:</strong> <code>:latest</code> is mutable—it points to a different image over time. Two different deployments at different times will run different versions. You cannot roll back to a previous state because you don't know what :latest was. Never use <code>:latest</code> in production.\n</div>\n<h5 style=\"margin-top: 1.25rem; font-size: 1.05rem; font-weight: 600\">3.1. Recommended Tagging Strategies</h5>\n<div style=\"padding: 2px; border-radius: 8px; font-size: 14px; margin-top: 0.5rem\">\n<div class=\"code\"><div class=\"code-head\"><span>bash</span><button class=\"copy\" type=\"button\">Copy</button></div><pre><code class=\"hljs\"><i class=c># ── STRATEGY 1: Git Commit SHA (Most Traceable) ────────────────────</i>\n<i class=c># Build and tag with commit SHA</i>\ndocker build -t myapp:$(git rev-parse --short HEAD) .\ndocker tag myapp:$(git rev-parse --short HEAD) myregistry.com/myapp:$(git rev-parse --short HEAD)\ndocker push myregistry.com/myapp:$(git rev-parse --short HEAD)\n\n<i class=c># Benefits: Exact mapping to source code, immutable, perfect traceability</i>\n<i class=c># Example: myapp:a1b2c3d</i>\n\n\n<i class=c># ── STRATEGY 2: Semantic Versioning + Build Metadata ──────────────</i>\n<i class=c># Tag with version from git tag</i>\nVERSION=$(git describe --tags --abbrev=0)\nBUILD=$(git rev-parse --short HEAD)\ndocker build -t myapp:$ {VERSION}-$ {BUILD} .\ndocker tag myapp:$ {VERSION}-$ {BUILD} myregistry.com/myapp:$ {VERSION}\ndocker push myregistry.com/myapp:$ {VERSION}\ndocker push myregistry.com/myapp:$ {VERSION}-$ {BUILD}\n\n<i class=c># Example: myapp:1.2.3 (major version), myapp:1.2.3-a1b2c3d (specific build)</i>\n\n\n<i class=c># ── STRATEGY 3: Environment + Timestamp ───────────────────────────</i>\nTIMESTAMP=$(<i class=b>date</i> +%Y%m%d-%H%M%S)\ndocker build -t myapp:$ {TIMESTAMP} .\ndocker tag myapp:$ {TIMESTAMP} myregistry.com/myapp:staging\ndocker push myregistry.com/myapp:staging\n\n<i class=c># Example: myapp:staging (always the latest staging), myapp:20240330-143022 (specific)</i>\n\n\n<i class=c># ── STRATEGY 4: Multiple Tags (Best Practice) ─────────────────────</i>\n<i class=c># Tag with multiple identifiers for flexibility</i>\nCOMMIT_SHA=$(git rev-parse --short HEAD)\nVERSION=$(git describe --tags --abbrev=0 2&gt;/dev/null || <i class=b>echo</i> <i class=s>&quot;dev&quot;</i>)\n\ndocker build -t myapp:$ {COMMIT_SHA} .\n\n<i class=c># Tag with semantic version (if available)</i>\n<i class=k>if</i> [ -n <i class=s>&quot;<i class=v>$VERSION</i>&quot;</i> ]; <i class=k>then</i>\n  docker tag myapp:$ {COMMIT_SHA} myapp:$ {VERSION}\n  docker push myapp:$ {VERSION}\n<i class=k>fi</i>\n\n<i class=c># Always tag latest for convenience (but never use in production)</i>\ndocker tag myapp:$ {COMMIT_SHA} myapp:latest\ndocker push myapp:latest\n\n<i class=c># In production deployments, always reference the commit SHA</i>\nkubectl <i class=b>set</i> image deployment/myapp myapp=myapp:a1b2c3d\n\n\n<i class=c># ── BEST PRACTICE SUMMARY ──────────────────────────────────────────</i>\n<i class=c># - Use immutable tags (commit SHA, timestamp) for production</i>\n<i class=c># - Use environment tags (staging, production) as mutable pointers</i>\n<i class=c># - Never use :latest in production</i>\n<i class=c># - Keep tags short but meaningful (8-char SHA is sufficient)</i>\n<i class=c># - Delete old tags to manage registry storage</i></code></pre></div>\n</div>\n<div style=\"margin-top: 1rem; border-left: 4px solid #3b82f6; padding: 1rem; border-radius: 4px; font-size: 0.9rem\" data-box=\"1\">\n<strong>🎯 Interview Answer:</strong> \"Production tagging must use immutable tags. The best practice is to tag with the Git commit SHA (e.g., myapp:a1b2c3d) because it provides exact traceability to source code. Additionally, tag with semantic version if you're doing releases (e.g., myapp:1.2.3). The <code>:latest</code> tag should only be used for local development—never in production, because it's mutable and you lose the ability to know exactly what version is running. For deployment, reference the immutable tag (SHA) in your Kubernetes manifests or Docker Compose files.
