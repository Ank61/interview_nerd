Scalability is about <em>you</em> surviving the spike. Your worker calls <code>ReceiveMessage</code> in a loop, saying in effect \"have you got anything for me?\" This asking is commonly called <strong>polling</strong>. SQS will not open a connection to you, will not call a webhook, and does not need your worker to have a public address, a DNS name or an open inbound port.</p>\n<p style=\"line-height: 1.75\">That has real consequences. Workers can live in a private subnet with no inbound internet access. Consumers control their own pace — a worker that is busy simply does not ask for more, so it can never be overwhelmed by a producer sending faster than it can cope (this natural brake is called backpressure). And scaling is trivially horizontal: start ten more workers and they all just start asking.</p>\n<p style=\"line-height: 1.75\">The trade-off is that a naive polling loop asking every 50 ms wastes money and CPU when the queue is empty. SQS solves this with <strong>long polling</strong> — you ask SQS to hold the request open for up to 20 seconds and reply the moment a message appears. You get near-instant delivery with a tiny fraction of the API calls. Set <code>ReceiveMessageWaitTimeSeconds</code> to 20 on essentially every queue you create.</p>\n<p style=\"line-height: 1.75\">If you want SQS-like durability with true push, the AWS answer is to combine services: Amazon SNS or EventBridge pushes to subscribers, and a very common architecture has SNS fan out to several SQS queues so each consuming team gets its own durable buffer. Messages have a retention period — by default 4 days, configurable from 60 seconds up to 14 days — after which SQS deletes them whether or not anyone read them. You cannot query messages by field, you cannot read a message without taking it out of circulation, and you cannot read the same message twice on purpose from two independent applications. Those are database and event-streaming jobs (DynamoDB, Amazon Kinesis, Amazon MSK), not queue jobs.</p>\n<h4 style=\"margin-top: 1.5rem; font-size: 1.25rem; font-weight: 600\">Common beginner misconceptions</h4>\n<ul style=\"margin-left: 1.5rem; list-style: disc; line-height: 2\">\n<li><strong>\"A queue makes my system faster.\"</strong> It makes the <em>response</em> faster, not the work faster.
